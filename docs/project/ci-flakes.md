# CI flake ledger

The classes of CI failure the project currently tolerates with a rerun, so
that a rerun on a release candidate can be checked against a published list
rather than taken on trust. A failure that matches no row is a finding,
never a rerun. A class leaves this table when its fix lands; the CHANGELOG
is the record of the fix and a recurrence after it is a regression.

**How a row is used.** Before rerunning a red job, confirm two things: the
failure matches the row's symptom, and the change under test cannot reach
the failing code (for a library-code change, `git show --stat <sha>` lists
no path the test exercises). Then `gh run rerun <id> --failed`. Every
sighting updates the row's last-seen run. A class seen twice with a
mechanism in our code is hardened, not rerun again; the "Rule" column says
which.

**Where the numbers come from.** The weekly `ci-health` workflow reports
rerun counts per job over the last seven days in its step summary and CSV
artifact, and prints an `ALERT` line for any job rerun twice or more. An
`ALERT` with no matching row here is a finding. A test failure that used
to surface under `build (<platform>)` now surfaces under
`test (<platform>, <pass>, k/n)`; the rows below keep the historical job
name of each sighting. The nightly `ci-nightly` dispatch opens or updates
an issue labelled `ci-nightly` when its run is red; a sighting there is
recorded in this ledger like any other. The other two ledgers are
`known_flaky` rows in `scripts/interop/expectations.toml` (interop cells)
and `environmental` entries in `tests/coverage/skip-ledger.toml`
(timing-sensitive skipped tests).

**Capability skips are not flakes.** A test that needs something a host may
lack (loopback multicast, `ffprobe`, TSDuck) records a capability skip and
returns. Where CI knows the capability is present it sets
`TST_REQUIRE_<CAP>=1`, and the skip fails the test instead; the Linux legs
require `MULTICAST`. Elsewhere each skip is appended to the file
`TST_CAPABILITY_LOG` names, and the `ci` job's step summary lists every skip
the leg took, with its count. The IPv6 UDP multicast test records
`MULTICAST_V6` and skips on every host until the UDP receiver accepts
`?iface=` for IPv6, so no leg requires it and it stays on every summary.

A defect that escaped the release qualification is not a flake; it is a row
of the [release findings ledger](/docs/project/release-findings.md).
