# 1.0 exit criteria

This page lists what must be true before the workspace tags 1.0. It
carries no date: 1.0 ships when every criterion below holds, not on a
calendar. Each criterion names the check that proves it, so a team
outside the project can confirm it from the repository and its CI runs
without asking anyone.

"Proved by" names a CI workflow, a script under `scripts/`, a file under
`tests/coverage/`, or a page section. "Today" says where the criterion
stands on `main` as of the page's last revision; it is context, not a
promise.

## Decisions

Seven maintainer decisions define the criteria below, which cite them by
number.

1. **Provisional modules under 1.0 semver.** Hybrid. `tst-hls` and
   `tst-rist` stay on their own 0.x version line while the Stable crates go
   1.0. A Provisional module inside a 1.x crate is exempt from that crate's
   1.x semver by the module table; the semver-checks gate at 1.0 judges
   Stable rows only.
2. **Mobile bindings and browser playback.** WebRTC playback is a 1.0
   requirement and may be Provisional at 1.0. The UniFFI binding is not;
   it lands in a 1.x minor as an additive binding.
3. **`DemuxFromFile`.** Removed in 0.9.0, not carried to 1.0. Its
   deprecation note says "removal no earlier than 1.0", so the 0.9.0
   CHANGELOG BREAKING entry states that the removal is earlier than the
   note promised and names `TryDemuxFromFile` as the replacement.
4. **The soak tree.** The 72-hour soak runs on the release-prep head: the
   version sweep lands before the freeze, and after the soak only the
   CHANGELOG date commit and the archive entry follow, so no path under
   `crates/` or `bindings/` changes between the soaked and the tagged
   commit. The qualification record names both commits and checks that
   diff. The requirement applies when a run qualifies a release (a `v*`
   tag, or a dispatch that says so); mid-cycle runs stay GO-able and show
   the soak as absent. The real-capture corpus test runs on the same host
   before the soak and gates the release the same way.
5. **The CI flake ledger.** A committed table, the
   [CI flake ledger](/docs/project/ci-flakes.md), one row per active flake
   class: the job, the symptom, the cause, first and last sighting run ids
   and the rule for the next sighting; closed classes name the release that
   shipped the fix. CI rerun
   rates are read from the weekly `ci-health` workflow's step summary and
   CSV artifact; no in-tree copy is kept.
6. **The C surface.** Every `:unaudited` cell in
   `tests/coverage/surface-manifest.toml` reaches zero before 1.0, in all
   three binding columns (c, python, java).
7. **Severity.** The working definition in section 6 stands. The issue
   label `severity-high` marks it.

## 1. Surfaces

Every module is classified in the module table of
[API stability](/docs/reference/api-stability.md). That table is the
source of truth; this section only says which rows 1.0 needs.

**Must be Stable at 1.0.** Every row that is Stable today stays Stable. The
rows the project's scope rests on are named here so a reader can check
them first:

| Surface | Rows in the module table |
|---|---|
| MPEG-TS mux and demux | `tst-core` `mpegts`, `io_file`, `shared` |
| KLV substrate and MISB ST 0601 | `tst-core` `klv`, its machinery rows, `klv::st0601` |
| Primary video codecs | `tst-core` `codec`, `codec::util`, `codec::h264`, `codec::h265` |
| Transport contract and errors | `tst-core` `transport`, `error`, `cancel`, `net`, `url` |
| SRT | `tst-srt` `(crate)` |
| The pipeline shells and reconnect | `tst-pipeline` `mux_sender`, `sender`, `raw_sender`, `demux_receiver`, `receiver`, `raw_receiver`, `managed_demux_receiver`, `managed_receive`, `reconnect`, `shell_error` |
| UDP, TCP, RTP | `tst-udp` `(crate)`, `tst-tcp` `(crate)`, the Stable `tst-rtp` rows |
| The C ABI | `tstrans.h` under the rules in section 3 |

**May stay Provisional at 1.0.** The newer codecs (`codec::h266`,
`codec::av1`) and audio parsers; the typed KLV sets other than ST 0601;
`tst-hls` and `publisher`; the RTSP server and its publisher role
(`tst-rtp` `rtsp`); `tst-rist`; the binding handle layer
(`tst-pipeline::binding`) and the URL openers and shells the bindings use.
Each Provisional row says what would let it move in its "Before Stable"
column.

**Planned surfaces.** The WebRTC playback surface (decision 2) must ship
before 1.0 and may be Provisional at the tag. The UniFFI binding is not a
1.0 requirement; it may land in a 1.x minor as an additive binding.

| Criterion | Proved by |
|---|---|
| Every public module has exactly one row, and every row names a real module | `scripts/check/rust/api-stability-coverage.sh`, run by the ratchets sweep in `ci.yml` |
| Every Provisional row has a "Before Stable" clause | `scripts/check/rust/api-stability-coverage.sh` fails on a Provisional row whose Before Stable cell is empty |
| No row is Experimental | the module table |
| The WebRTC playback surface has a row | the module table names the crate and module with a tier and, if Provisional, a Before Stable clause |

## 3. C ABI

The rules are the ones the "Versioning" section of the
[binding-authors guide](/docs/reference/binding-authors.md#versioning)
states: `TST_ABI_VERSION_MAJOR` moves on an incompatible change,
`TST_ABI_VERSION_MINOR` on an additive one, `TST_ABI_VERSION_PATCH` on a
fix that keeps shape and behaviour. Three checks enforce them, in the order
a change meets them:

| Check | Where it runs | What it refuses |
|---|---|---|
| The stale-header refusal | every CI build of `tst-c` | a regenerated `tstrans.h` that differs from the committed `bindings/c/include/tstrans.h` |
| `scripts/check/c/abi-symbols.sh` | the `build` job in `ci.yml` | an exported name not in `bindings/c/abi-symbols.txt`; a name present at the previous tag and gone now; a name added without a higher minor |
| `scripts/check/c/abi-compat.sh` | the `c-abi` job in `ci.yml` and the qualification run | an `abidiff` change against the previous tag's library: a removed or changed function, a struct that grew or moved, a renumbered enumerator, an addition without a minor bump |

**At the 1.0 bump:**

| Criterion | Proved by |
|---|---|
| `TST_ABI_VERSION_MAJOR` becomes 1 | the constant in `bindings/c/core/src/lib.rs` and the committed header; `scripts/check/repo/release-version-consistency.sh` |
| The `c-abi` job passes the previous and current majors to `abi-compat.sh`, the way it passes the minors today | the `c-abi` job in `ci.yml` (its comment marks this as a 1.0 item); without it, the intended break fails the job |
| `abi-symbols.sh` accepts the removals the 1.0 major makes | the script; today a removed name fails whatever the major, by design before 1.0 |
| Every struct added from 1.0 starts with a size field | the struct definitions in `tstrans.h`; the "How these rules are checked" section of the binding-authors guide states the rule |
| The existing stats structs convert to the size-field shape once, at the 1.0 major | the 1.0 header against the last 0.x header in the `abi-compat.sh` report of the qualification run |
| `bindings/c/abi-symbols.txt` becomes the input of the distribution's symbols file | the distribution packaging reads it; no hand-written symbol list exists beside it |
| The 1.0 candidate's qualification record shows the C ABI leg compatible | the `abi.json` entry of the record (verdict `compatible`) |
| No `:unaudited` cell remains in the surface manifest, in any binding column | `bash scripts/check/repo/surface-manifest.sh` with `UNAUDITED_CELLS_MAX` at `0 0 0` for c, python and java (decision 6); every cell is a real symbol, `:deferred` or `:n/a` |

## 6. Acceptable open findings

1.0 may ship with open issues, under these limits:

| Criterion | Proved by |
|---|---|
| No open correctness finding of high severity | no open issue carries the `severity-high` label. High severity (decision 7): wrong bytes on the wire or in a decoded record, data lost without a counter or an error saying so, a crash or hang in library code, or memory unsafety. Security reports follow [SECURITY.md](/SECURITY.md) |
| Every known flake is listed with its ledger entry | CI flake classes are the rows of the [CI flake ledger](/docs/project/ci-flakes.md) (decision 5; a failure matching no row is a finding); interop flakes are the `known_flaky` rows in `scripts/interop/expectations.toml`; timing-sensitive skipped tests are the `environmental` entries in `tests/coverage/skip-ledger.toml`; CI rerun rates are the latest `ci-health` workflow run's step summary (`scripts/dev/ci-health.sh`, weekly). The 1.0 release notes list each with its entry |
| No test is disabled for a bug | the contents of `tests/coverage/skip-ledger.toml`: no `blocked_bug` entry without `resolved`. `scripts/check/repo/skip-ledger-sync.sh` keeps the file in step with the code's `#[ignore]` attributes and their dates; it does not fail on an active entry, so the file is the proof |
| Every documented deferral was read again and confirmed once before 1.0 | each entry in [deferred features](/docs/project/deferred-features.md) still holds its "Why deferred" and "Trigger to revisit"; an entry whose trigger has fired is either built or restated as post-1.0 |
