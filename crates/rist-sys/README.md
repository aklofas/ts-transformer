# tstrans-rist-sys

Raw FFI bindings to VideoLAN librist 0.2.x, generated by bindgen. It ships
no safe wrapper — see `tst-rist` for the safe API tstrans applications use.

**Bundled source.** This crate packages the pinned librist v0.2.20 tree and
builds it when no suitable system librist >= 0.2.10 is found via
pkg-config. Set `RIST_FORCE_VENDORED=1` to force the vendored build even
when a system librist is present. The build compiles a copy of that tree
in `OUT_DIR` carrying one correction: the Simple-profile receiver checks
its RTCP peer (port + 1) for null before using it, so a failed RTCP bind
returns an error instead of crashing. A system librist 0.2.20 lacks this
fix.

**Build prerequisites:** a C toolchain, meson, and ninja (for librist —
Debian/Ubuntu: `apt install meson ninja-build`), plus libclang (for
bindgen) — see the `bindgen` crate's requirements for platform-specific
libclang setup.

**LZ4:** librist >= 0.2.17 needs LZ4 for Advanced Profile payload
compression. The vendored build enables librist's bundled LZ4
(`-Dbuiltin_lz4=true`) so it never depends on a system `liblz4`.

**Stability: Internal.** This crate is an implementation detail of the
tstrans workspace. You should not depend on it directly.

**License:** this crate is MIT OR Apache-2.0. The bundled librist source
is BSD-2-Clause — see `vendor/librist/COPYING`. When the `mbedtls`
feature is enabled, mbedTLS is bundled at build time via
`tstrans-mbedtls-src`; librist links that shared mbedTLS 3.6.x instead of
its own bundled `contrib/mbedtls` (2.26.0, Apache-2.0), which this
package excludes since our vendored build never compiles it (librist's
meson build only needs `contrib/mbedtls/meson.build` to resolve the
external dependency at configure time).
